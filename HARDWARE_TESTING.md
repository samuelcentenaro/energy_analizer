# 🔬 Hardware Testing & Validation Guide\n\n**Energy Analyzer ESP32 - Phase 1 Verification**\n\n---\n\n## 🎯 Objective\n\nValidate that:\n- ✅ ESP32 board is powered and responding\n- ✅ ADS1015 ADC is communicating via I2C\n- ✅ Voltage and current measurements are being read\n- ✅ Firmware initializes without crashes\n- ✅ Serial communication is working\n\n---\n\n## 📋 Prerequisites\n\n- [ ] ESP-IDF v5.1+ installed and configured\n- [ ] Energy Analyzer firmware compiled successfully\n- [ ] ESP32 board ready with USB cable\n- [ ] Multimeter for validation (optional but recommended)\n- [ ] Serial monitor software (built into idf.py)\n\n---\n\n## 🔌 Hardware Setup\n\n### Step 1: Connect USB Cable\n\n1. **Plug USB cable into ESP32 board**\n   - Use USB-C or Micro-USB (depends on your board variant)\n   - Connect to computer USB port\n2. **Verify detection on Windows**\n   ```powershell\n   # List all COM ports\n   [System.IO.Ports.SerialPort]::GetPortNames()\n   ```\n   - Expected output: `COM3`, `COM4`, etc.\n   - Note your port number\n3. **Check Device Manager** (alternative verification)\n   - Right-click \"This PC\" → \"Manage\"\n   - Device Manager → Ports (COM & LPT)\n   - Look for `CH340 USB UART` or `CP2102` (depending on board)\n\n### Step 2: Visual Inspection\n\n- [ ] Board LEDs blinking (power indicator)\n- [ ] No burning smell\n- [ ] All components soldered properly\n- [ ] No visible damage to ZMPT101B or SCT013 sensors\n\n---\n\n## ⚡ Flashing Firmware\n\n### Configure Environment\n\n```powershell\n# Set ESP-IDF path (if not already set)\n$env:IDF_PATH = \"C:\\Users\\samuelcentenaro\\esp\\Espressif\\frameworks\\esp-idf-v5.1\"\n\n# Navigate to project\ncd \"C:\\Users\\samuelcentenaro\\OneDrive\\Documentos\\Projetos\\Sistemas Embarcados\\Energy Analizer\"\n```\n\n### Flash to Board\n\n**Replace `COM3` with your actual port number!**\n\n```powershell\n# Flash firmware and start monitor (recommended)\npython \"$env:IDF_PATH\\tools\\idf.py\" -p COM3 flash monitor\n\n# OR just flash (without monitor)\npython \"$env:IDF_PATH\\tools\\idf.py\" -p COM3 flash\n\n# OR monitor only (if already flashed)\npython \"$env:IDF_PATH\\tools\\idf.py\" -p COM3 monitor\n```\n\n### Expected Output\n\n After flashing, you should see logs appearing:\n\n```\nBuilding...\nFlashing...\n\n--- idf_monitor on COM3 115200 ---\nESP-IDF v5.1-dev ...\n\nI (0) boot: ESP32 revision c3\nI (0) boot: clk_drv=0x00,q_drv=0x00,d_drv=0x00,cs0_drv=0x00\n...\n[PHASE 1] Initializing ADS1015 ADC sensor...\nI2C bus initialized\nADS1015 detected at address 0x48\nADC configured: 2 differential channels @ 1600 SPS\nADC configured: 2 differential channels @ 1600 SPS\n[PHASE 1] ADC sensor initialized successfully!\n  Sampling rate: 8000 Hz\n  RMS window: 4000 samples (~500 ms)\n  Voltage: offset=0.00 mV, scale=1.000000\n  Current: offset=0.00 mA, scale=1.000000\n```\n\n✅ **If you see \"ADC sensor initialized successfully!\" → HARDWARE IS ALIVE**\n\n---\n\n## 🧪 Test Cases\n\n### Test 1: Board Initialization (MUST PASS)\n\n**Procedure:**\n1. Flash board and monitor\n2. Watch for initialization messages\n3. Check for any error logs\n\n**Pass Criteria:**\n- Messages appear cleanly\n- No \"ERROR\" tags in logs\n- ADC initialization completes without timeout\n\n**Expected:** `[PHASE 1] ADC sensor initialized successfully!`\n\n---\n\n### Test 2: ADC Sampling (CRITICAL)\n\n**Procedure:**\n1. Ensure AC supply is connected to ZMPT101B\n2. Ensure current sensor is clamped around a live AC wire (or simulate with resistor ladder)\n3. Monitor logs for RMS readings\n\n**What to look for:**\n```\nI (xxx) ADC_SENSOR: Read: U=220.00V (peak=311.00), I=12.30A (peak=17.38), samples=4000\nI (xxx) ADC_SENSOR: Read: U=220.00V (peak=311.00), I=12.30A (peak=17.38), samples=4000\n```\n\n**Pass Criteria:**\n- RMS voltage appears every ~500ms\n- RMS current appears every ~500ms\n- Values are within expected range (not zero, not maxed out)\n- Sample count reaches 800\n\n**Fail Indicators:**\n- `RMS validation failed` message → ADC reading is out of range\n- `Insufficient samples` → ADC not sampling fast enough\n- `Voltage RMS out of range` → Check wiring, calibration\n\n---\n\n### Test 3: No Current Input (Baseline Test)\n\n**Procedure:**\n1. Disconnect current sensor (or open the clamp)\n2. Monitor RMS values\n3. Current should read near zero (or small offset)\n\n**Expected Output:**\n```\nU=220.00V (peak=311.00), I=0.12A (peak=0.18), samples=800\n```\n\n**Pass Criteria:**\n- Current RMS < 0.5A when disconnected\n- If >1A, ADC offset needs calibration\n\n---\n\n### Test 4: Frequency Measurement (VALIDATION)\n\n**Procedure:**\n1. Look for frequency logs (when Phase 3 implemented)\n2. Expected frequency = 60 Hz (Brazil)\n3. Tolerance: ±0.5 Hz nominal\n\n**Expected:**\n```\nFrequency: 59.8 Hz to 60.2 Hz\n```\n\n---\n\n### Test 5: WiFi Connectivity (Phase 4)\n\n**When Display & MQTT implemented:**\n1. Check OLED menu for WiFi networks\n2. Select your network\n3. Monitor should show:\n```\nWi-Fi connected\nMQTT connected\nPublishing to broker...\n```\n\n---\n\n## 📊 Multimeter Validation (Optional but Recommended)\n\n**Voltage Accuracy Test:**\n\n1. **Set multimeter to AC voltage**\n2. **Measure AC supply voltage with multimeter**\n   - Expected: ~220V RMS in Brazil\n3. **Compare with ESP32 reading in logs**\n   - Should match within ±2V (before calibration)\n   - Should match within ±2V (after calibration)\n\n**Current Accuracy Test:**\n\n1. **Set multimeter to AC current mode (clamp meter)**\n2. **Measure current on a live circuit**\n3. **Compare with ESP32 reading**\n   - Should match within ±0.5A (before calibration)\n   - Should match within ±0.2A (after calibration)\n\n---\n\n## ❌ Troubleshooting\n\n### Issue: No COM port appears\n\n**Solutions:**\n1. Check Device Manager (see Hardware Setup Step 2)\n2. Try different USB cable\n3. Try different USB port\n4. Check board power LED (should be lit)\n5. If using bus-powered ESP32, may need external power\n\n### Issue: Flash fails with \"Failed to open port\"\n\n**Solutions:**\n```powershell\n# Close other serial monitors\n# Try different port\npython \"$env:IDF_PATH\\tools\\idf.py\" -p COM4 flash monitor\n\n# Reset board before flashing\n# (Press EN button on ESP32)\n```\n\n### Issue: \"ADC not running\" error\n\n**Possible causes:**\n1. Initialization failed silently\n2. Mutex creation failed (memory issue)\n3. ADC hardware error\n\n**Debug steps:**\n1. Check for errors in initialization logs\n2. Verify GPIO35/34 not used elsewhere\n3. Try recompiling with fresh build directory\n\n### Issue: RMS values are all zeros\n\n**Possible causes:**\n1. ADC offset wrong (see calibration)\n2. ADC scale factor wrong\n3. Sensors not connected\n4. ADC pins damaged\n\n**Debug steps:**\n1. Check HARDWARE_DIAGRAM.md for pin connections\n2. Verify ZMPT101B and SCT013 are powered\n3. Multimeter check: measure voltage at GPIO35/34\n4. If 0V → sensor issue; if 1.65V → good (rest mode)\n\n### Issue: Monitor shows garbled text\n\n**Solutions:**\n```powershell\n# Baud rate may be wrong, try explicit setting\npython \"$env:IDF_PATH\\tools\\idf.py\" -p COM3 monitor --baud 115200\n```\n\n---\n\n## 🎉 Success Checklist\n\nIf all tests pass, check the following:\n\n- [ ] Board initializes cleanly (no errors)\n- [ ] ADC sampling shows RMS every 500ms\n- [ ] Voltage reading matches multimeter (±5V without calibration)\n- [ ] Current reading changes when sensor input changes\n- [ ] Logs appear smoothly without stuttering\n- [ ] No \"ERROR\" tags in complete 1-minute log run\n- [ ] Repeated measurements are consistent\n- [ ] Board doesn't reset unexpectedly\n\n**If all 8 items checked:** ✅ **HARDWARE VALIDATED - READY FOR PHASE 2**\n\n---\n\n## 📝 Log File Capture (For Troubleshooting)\n\nCapture complete logs for analysis:\n\n```powershell\n# Redirect logs to file\npython \"$env:IDF_PATH\\tools\\idf.py\" -p COM3 monitor > energy_analyzer_test.log 2>&1\n\n# Run for 1-2 minutes, then Ctrl+C\n# Share log file for debugging\n```\n\n---\n\n## 🔗 Next Steps (After Hardware Validation)\n\n1. **Calibration**\n   - See docs/CALIBRATION_PROCEDURE.md\n   - Measure with multimeter, update offset/scale in config\n   - Save calibration to NVS flash\n\n2. **Phase 2: Display & UI**\n   - Implement SSD1306 OLED\n   - 3-page menu system\n   - Button interface\n\n3. **Phase 3: Signal Analysis**\n   - FFT harmonic calculation\n   - THD computation\n   - SAG/SWELL detection\n\n4. **Phase 4: WiFi & MQTT**\n   - Network scanning\n   - Broker connection\n   - Data publishing\n\n---\n\n**Document:** Hardware Testing & Validation  \n**Project:** Energy Analyzer ESP32  \n**Status:** 🟢 Ready for Testing (After Build)  \n**Last Updated:** April 6, 2026\n"
